## 4. 产品定位与设计原则
> **不是通用记账 App，是一台「每日额度执行器 ＋ 存款进度仪」。** 只回答两个问题：**今天还能花多少？距离 2/5 的 1 万还差多少？**

| # | 原则 |
|---|---|
| ★1 | 首页**只显示「剩余」，不显示「已花」**（剩余框架抑制消费） |
| ★2 | 全 App **永不出现红色/感叹号/警告**；超支只是「今天用完了」，灰掉 |
| ★3 | **正反馈当天到账**：晚间结算「今天省下 21.40，已进余粮」是唯一爽点 |
| ★4 | **允许漏记**：不追问、不补红点、不弹窗、不催 |
| ★5 | 每步都能「稍后」；只有③储蓄跳过后提示**一次**，绝不唠叨 |
| ★6 | 记一笔 ≤2 击；冷启动 <1.5s；100% 离线可用 |

## 7. ★三类流水模型（设计地基）
| 类型 | 定义 | 例子 | 影响总资产 | 计入日额度 |
|---|---|---|---|---|
| **Expense 支出** | 钱真的消失 | 午饭15、猫粮68、奶茶20 | 减少 | **是** |
| **Transfer 划转** | 钱只是换地方 | ②→①55.19；①→③1,855.17；①→②21.40 | **不变** | **否** |
| **Special 专项** | 从③出的计划内大额 | Q4水电405.88、理发43.40、猫看病300 | 减少 | **否**（单列） |

> ★★★ **还花呗/月付/白条/放心借 ＝ Transfer(BANK1→BILL)，不是 Expense。** 那笔钱在消费当天已计入日额度，还款只是把钱搬到平台。记成支出＝同一笔钱算两次，日额度被击穿、储蓄全错。
> → **「记一笔」分类里永远不许出现「还款」。**

账户是枚举，不是三张表：
```js
const ACCT = { BANK1:'工资卡', POOL2:'余额宝', POCKET3:'小荷包',
               BILL:'账单平台', OUT:'外部支出' };
```

## 8. 状态机
**一天**
```
早上[②→① 55.19 · Transfer daily_alloc]
 → 白天[记支出 ×N · Expense]
 → 晚上[①→② 退结余 · Transfer daily_refund · DaySlot.closed=1]
 → 次日[额度重置]
```
3 天一结：一次划 165.57，第 4 天结算。

**发薪日**
```
到账 → 还账单(bill_repay) → 放预算到②(payday_budget) → 大头进③(payday_save)
     → 清②上期结余(pool_clear) → 开新期(批量生成 DaySlot)
```

## 12. 核心算法

### 12.1 金额（全项目唯一允许 Math.round 的地方）
```js
export const yuanToFen = y => Math.round(y * 100);
export const fenToYuan = f => (f / 100).toFixed(2);
export const sumFen    = a => a.reduce((s,x)=>s + x.amountFen, 0);   // 全程整数
```
`budgetOf(days) = RATE_FEN * days` 恒为整数 ⇒ **不存在任何浮点累加路径**。

### 12.2 日历与节假日
```js
export const DAY_TYPE = {
  '2026-09-20':'补班', '2026-09-25':'假','2026-09-26':'假','2026-09-27':'假',
  '2026-10-01':'假','2026-10-02':'假','2026-10-03':'假','2026-10-04':'假',
  '2026-10-05':'假','2026-10-06':'假','2026-10-07':'假','2026-10-10':'补班',
  '2027-01-01':'假'   // ⚠️ 2027 其余安排待核实后补全
};
const iso    = d => d.toISOString().slice(0,10);
const isRest = d => ([0,6].includes(d.getUTCDay()) && DAY_TYPE[iso(d)] !== '补班');
const isHoli = d => DAY_TYPE[iso(d)] === '假';

// 25 号逢休息日/法定假 → 前推到最近工作日
export function actualPayDay(y, m) {
  let d = new Date(Date.UTC(y, m-1, 25));
  while (isRest(d) || isHoli(d)) d.setUTCDate(d.getUTCDate() - 1);
  return iso(d);
}

// 计薪工作日 = 周一~五 − 法定假(落工作日) + 调休补班(落周期内)
export function workDays(startISO, endISO) {
  let n = 0;
  for (let d = new Date(startISO+'T00:00:00Z'); d <= new Date(endISO+'T00:00:00Z');
       d.setUTCDate(d.getUTCDate()+1)) {
    const w = d.getUTCDay(), t = DAY_TYPE[iso(d)];
    if (t === '补班') n++;
    else if (w >= 1 && w <= 5 && t !== '假') n++;
  }
  return n;
}
```
必须验证：`workDays('2026-09-21','2026-10-20') === 17`、`workDays('2026-12-21','2027-01-20') === 22`。

### 12.3 区间与预算
```js
export function rangeOf(idx) {          // 本期 = [本期到账日, 下期到账日−1]
  const start = EV[idx].payDateActual;
  const end   = idx === 4 ? DEADLINE    // ★末期用截止日收尾 → 12 天
                          : prevDay(EV[idx+1].payDateActual);
  return { start, end, days: diffDays(start, end) };
}
const budgetOf   = days => RATE_FEN * days;
const saveOf     = ev => ev.totalInFen - ev.billTotalFen
                          - budgetOf(ev.days) - (ev.specialOutFen || 0);
const pocketAt   = idx => Σ over i<=idx of (saveOf(EV[i]) - EV[i].specialOutFen);
```
★ **末期 12 天是硬编码特例，必须加注释说明原因**（2/5 出发，不是下个发薪日）。

### 12.4 聚合记忆化（性能）
```js
let cache = { key:null, val:null };
export const deriveAll = s => {
  const k = versionKey(s);                    // 流水长度+最大id
  if (cache.key === k) return cache.val;
  cache = { key:k, val: compute(s) };
  return cache.val;
};
```

## 13. 技术架构与选型

**分层（依赖只能向下）**
```
View(WXML/WXSS+组件) → Page(编排) → Store(单例+订阅)
   → Domain(纯函数 money/plan/ledger/calendar) → Data(storage + 预置JSON + 可选cloud)
```

**四个核心决策**
| # | 决策 | 反面 | 理由 |
|---|---|---|---|
| 1 | **本地优先** | 全走云数据库 | 高频＋离线场景；启动 0 延迟；个人云额度有限 |
| 2 | **派生余额，不存死值** | 余额写进 storage | 存死值一旦写坏永久错误；派生可重算、可回溯、可改参数重跑 |
| 3 | **零后端** | 自建服务＋MySQL | 单人无协作需求，0 成本 0 运维 |
| 4 | **金额全程整数分** | float 存元 | 135 天累加必出 0.01 误差且无法定位 |

**小程序运行时（双线程）约束**
```
微信 Native ── JSBridge/JSAPI
   ├ 渲染层 WebView(WXML/WXSS)  ◄─ setData(序列化) ─►  逻辑层 JSCore(无DOM/window)
```
| 约束 | 对策 |
|---|---|
| 逻辑层无 DOM/window | 不引 DOM 类库，图表手写 Canvas |
| setData 跨线程序列化 | **局部 setData** 只传变化字段，禁止整页重推 |
| 每日结算触发全量聚合 | 聚合记忆化（§12.4） |
| 主包 2MB 上限 | 无 UI 框架、图标用 CSS/字体、预置 JSON <10KB |
| 页面栈 ≤10 | tabBar 5 页，不 navigateTo 套娃 |

**选型结论**：原生小程序（WXML/WXSS/JS）；状态＝单例+订阅（50 行，**不用 Redux/MobX/vuex**）；UI＝5 个自定义组件（**不用 Vant/WeUI/ECharts**）；只有当你熟 React 且要同时出 H5 时才考虑 Taro，熟 Vue 才考虑 uni-app —— 本需求**不需要多端**。

export const subscribe = fn => (subs.add(fn), () => subs.delete(fn));

## 15. 持久层与版本迁移
```js
const KEY='p5519', SCHEMA=3;               // 结构每变一次 +1
export function load() {
  const raw = wx.getStorageSync(KEY);
  if (!raw) return seed();                 // 首次注入 data/plan-2026.json
  return migrate(JSON.parse(raw));         // v1→v2→v3 逐版升级
}
export function persist(s) {               // 写失败降级为内存，不崩
  try { wx.setStorageSync(KEY, JSON.stringify(s)); } catch (e) { markDirty(); }
}
```
| 要点 | 说明 |
|---|---|
| **必须带 schemaVersion** | 日后加字段，老数据不迁移会直接白屏 |
| 上限 10MB | 一天 5 笔×一年≈200KB，绰绰有余 |
| 立即写、不节流 | 记一笔低频，丢一条比卡一下严重 |
| 冷启动 | onLaunch 里 load+seed 完成即就绪，页面只读派生 |

## 16. 提醒与推送（含真实限制）
**微信「长期订阅消息」只对政务/医疗/交通/金融/教育等类目开放；个人主体工具类通常只能用「一次性订阅」——授权一次只能发一条。**
```
主方案：一次性订阅 + 顺手续订
  · 第 3 笔「记一笔」后弹「是否接收结算提醒」
  · 引导勾选「总是保持以上选择，不再询问」→ 之后静默续订
兜底方案（★推荐当成一等功能，不依赖推送）
  · 小程序图标角点：今日未结算 +1
  · 导出 .ics：5 个发薪日写进手机系统日历，标题直接写「转③ 1,855」
```
> 系统日历比订阅消息可靠得多，**别把宝押在推送上**。
