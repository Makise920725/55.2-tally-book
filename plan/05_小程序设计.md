# 微信小程序设计文档｜「55.19」每日额度记账

> 一句话定位：**这不是通用记账 App，是一台「每日额度执行器 + 存款进度仪」。** 记账只是副产品，核心只回答两个问题：
> **① 今天还能花多少？ ② 距离 2/5 的那 1 万还差多少？**

---

## 一、为什么不做通用记账

通用记账 App（随手记、一木记账）失败率高，因为它只**记录**、不**约束**。你的节奏很特殊：

- 早上从余额宝划 55.19 进工资卡
- 白天只刷工资卡，超了就付不动
- 晚上把没花完的退回余额宝
- 发薪日走五步，大头当天锁进小荷包
所以这个 App 的唯一价值是：**把这套节奏变成 3 秒能完成的动作，并把「省下来的钱」变成看得见的进度。**

---

## 二、核心机制：必须区分三类流水（记账 App 最容易搞错的地方）

| 类型 | 定义 | 例子 | 影响总资产 | 计入日额度 |
| --- | --- | --- | --- | --- |
| **① 支出 Expense** | 钱真的消失了 | 午饭 15、猫粮 68、奶茶 20 | 减少 | **是** |
| **② 划转 Transfer** | 钱只是换个地方 | 余额宝→工资卡 55.19；工资卡→小荷包 1,855.17；工资卡→余额宝 21.40 | 不变 | **否** |
| **③ 专项 Special** | 从③出的计划内大额 | Q4 水电 405.88、理发补差 43.40、猫看病 300 | 减少 | **否**（单列台账） |

**这是整个设计的地基。** 如果把「余额宝→工资卡」记成支出，日额度秒被击穿；如果把「还花呗」记成支出，等于同一笔钱算两次（花的时候已经算过了）。
> ⚠️ **还账单（花呗/月付/放心借/白条）＝ 划转，不是支出。** 它必须待在「账单」页，**永远不出现在「记一笔」的分类里**。

## 四、逐屏设计

### Tab 1「今日」— 打开就得到答案

```
+----------------------------+
| 9月25日 · 本期第 1/29 天      |
|                            |
|       今天还能花             |
|        ¥ 23.40             |
|     ((((      ))))  42%     |
|     55.19 - 已花 31.79      |
|                            |
|  [吃饭][猫][日用][零食]       |
|  [充电][衣物][娱乐][其他]     |
|                            |
|  [ 晚间结算：退回 21.40 ]     |
|                            |
|  今日流水：午饭15 猫粮...     |
+----------------------------+
```
**要点**

- **主视觉只有一个数字：还能花多少。** 不是「已花多少」——「剩余框架」抑制消费，「已花框架」诱发羞耻。
- 环形条随剩余变少而变细，颜色绿→黄→灰；**超支不用红色警告**。
- 记一笔＝2 次点击：点分类 → 数字键盘 → 自动保存。键盘预填「上次同类金额」，吃饭这类高频项可做到 1 次点击。
- 「晚间结算」按钮只在 20:00 后出现，点击显示「今天省下 21.40 元，已进余粮」——**这是全 App 当天唯一的爽点**，值得做小动画。

### Tab 2「本期」— 一周看一次的复盘页

```
本期 9/24 -> 10/22 (29天)   下期发薪 10/23
余额宝(2) 余粮      1,568.72
工资卡(1) 今日剩       23.40
本期预算 1,600.51 / 已花 31.79
##########################  <- 均值线 55.19
[][][][][][][][][][]...     <- 29 根每日柱

本期预测：按目前节奏，期末余额宝会剩 210.40
         这笔将在 10/23 全部转入小荷包
```
「期末预测」是行为学上的**目标梯度效应**：越接近目标越努力。让他看见「省下来会有多少」。

### Tab 3「储蓄」— 整个 App 的动机来源

```
小荷包(3)      ¥ 1,855.17

目标 10,000  |--|-------------|  还差 8,144.83
终点 11,992  |--|----------------|

+ 距 2027/2/5 出发还有 144 天 +

五期计划
[x] 9/24   转 1,855.17  ->   1,855
[ ] 10/23  转 1,352.12  ->   3,207
[ ] 11/25  转 2,866.01  ->   6,073
[ ] 12/25  转 2,452.59  ->   8,120  (水电 -405.88)
[ ] 1/25   转 3,915.13  ->  11,992  (理发 -43.40)

专项支出：12月 水电季缴 -405.88 / 1月 理发补差 -43.40
```
**要点**

- **进度条要画两条线**：10,000（心理目标）与 11,991.74（精算终点）。跨过 1 万那天的庆祝动画是设计重点。
- **必须把预期管理写进界面**：12/25 那期旁边直接印一行小字「这期后只有 8,120，要到 1/25 才破万——这是计划内的」。不写，用户会自己发现然后放弃。
- 每期卡片可点「已完成」→ 自动累加余额、开新一期；允许填实际金额，差额进「调节项」，不报错。

### Tab 4「我的」

- 参数：日额度 55.19 / 日薪 150 / 周期 21–20 / 截止日 2027-02-05 / 目标 10,000
- **情景切换**：省 48.29 ｜ 中 55.19 ｜ 松 63.73 → 全表自动重算
- 分类管理、金额校准（手填真实余额，差额记 adjust）、CSV 导出、订阅提醒开关

### 浮层 A：发薪日 SOP（当天自动弹出）

```
今天是发薪日 9/24 · 五步清单

[ ] 1. 工资+生活费到账  3,300 + 2,000 = 5,300
[ ] 2. 还 10 月账单 1,844.32
       花呗620.49 | 月付183.54 | 放心借417.79 | 白条622.50
[ ] 3. 余额宝(2)放预算 1,600.51 = 55.19 x 29 天
[ ] 4. 小荷包(3)存 1,855.17   <-- 最重要一步
[ ] 5. 余额宝上期结余 -> 也转小荷包

完成后本期开始，每天 08:00 提醒你划 55.19
```
### 浮层 B：超支确认（语气必须中性）

```
这笔 80.00 超过当日额度 55.19
差额 24.81 将从本期余粮支出

[ 确认 ]    [ 取消 ]
```
不要红色感叹号、不要「警告」字样。记账 App 最常见的死法是让用户产生羞耻感然后卸载。

## 五、一天的状态机

```
  早上          白天         晚上          次日
 +--------+   +--------+   +--------+   +--------+
 | 划出    |->| 记账xN |->| 结算    |->| 重置    |
 | 2 -> 1  |   | 支出    |   | 1 -> 2  |   | 额度    |
 | 55.19   |   |         |   | 退结余  |   | 55.19   |
 +--------+   +--------+   +--------+   +--------+
   划转          支出         划转           自动
```
- 早上那一步**可以不点**：App 支持「3 天一结」模式（一次划 165.57，第 4 天结算），给嫌麻烦的人一条退路。
- 晚上结算点击后**当天封账**（closed=1），不可再改，只能追加更正——防止事后篡改数字自欺。

## 六、发薪日的状态机

```
到账 -> 还账单(划转) -> 放预算到2 -> 大头进3 -> 清2上期结余 -> 开新期
```
每完成一步，③余额实时跳动；五步全完成触发一次「本期已存 1,855.17 元」反馈。

### PayEvent（发薪期，预置 5 行）

| 字段 | 例（第 1 期） |
| --- | --- |
| pay_date_actual / pay_date_nominal | 2026-09-24 / 2026-09-25 |
| reason_advance | 中秋假期首日 |
| range_start / range_end / days | 2026-09-24 / 2026-10-22 / 29 |

| budget_to_pool / save_to_pocket | 160051 / 185517 |
| special_out / pocket_after / status | 0 / 185517 / 未到账·已完成 |

### Expense（日常支出）

`id, date, category, amount, day_slot_id, note, created_at`

分类枚举：meal 吃饭 / cat 猫 / daily 日用 / snack 零食 / charge 充电 / cloth 衣物 / fun 娱乐 / med 医药 / other 其他。**不含「还款」。**

### Transfer（划转）

`id, date, from_acct, to_acct, amount, kind`

kind：`daily_alloc` 早间划额 / `daily_refund` 晚间退回 / `payday_budget` 发薪放预算 / `payday_save` 发薪转存 / `pool_clear` 上期结余清理 / `bill_repay` 还款

### DaySlot（每日额度，一行一天）

`date, pay_event_id, day_index, allocated, spent, refunded, closed`

spent 由 Expense 聚合、refunded 由 Transfer 聚合；`closed=1` 后不可再追加支出。

### PocketLedger（③小荷包流水）

`date, type(in/out), amount, reason, balance_after` — 用于期末对账与差异回溯。

### Adjust（校准）

`date, acct, real_balance, book_balance, diff, note` — 真实余额与账面差额来源，可随时追溯是漏记还是误差。

## 九、技术选型

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 框架 | 原生 WXML/WXSS/JS（熟 React 可用 Taro） | 无构建负担、审核最快 |
| 存储 | **本地 storage 为主**，云开发作备份 | 断网可用、启动 0 延迟 |
| 同步 | 云开发数据库（openid 天然隔离） | **不要做手机号注册/多人功能**，你一个人用 |
| 图表 | 手写 Canvas/CSS（一个环形 + 一组柱子） | 引 ECharts 包体积翻几倍，不值得 |
| 提醒 | 订阅消息 requestSubscribeMessage | 08:00 划额、22:00 结算、发薪日 SOP |
| 金额 | **一律用「分」存整数**，展示时 ÷100 | 浮点累加必出 0.01 误差 |
| 体积 | 主包 < 200KB | 目标 3 秒进到「今日」页 |

## 十、绕不开的限制（提前接受，别踩坑）

| 限制 | 影响 | 对策 |
| --- | --- | --- |
| 小程序**读不到**银行卡/余额宝/小荷包的实时余额 | ①②③只能是「账面推算值」 | 首页标注「账面余额，以银行为准」；提供**校准**入口，差额自动进 adjust 表 |
| 无法自动抓取微信/支付宝消费流水 | 必须手动记 | 「记一笔」压到 2 击；分类记住上次金额；漏记不影响账户逻辑 |
| 小荷包/余额宝无法从微信内直接跳转 | 「打开小荷包」只能靠提示 | 发薪日清单用「文字 + 一键复制金额」，而非自动跳转 |
| 订阅消息需用户授权，单次只能发一条 | 提醒可能断 | 引导勾选「总是保持以上选择」；关键提醒做成「长期订阅」模板 |
| 个人主体小程序不能碰「理财/收益」表述 | 审核风险 | 定位纯**记账 + 日程提醒**工具；页面不出现收益率、不推荐具体产品名 |
| 你不能在小程序里直接付款 | 它只能算账，不能替你花钱 | 所以「支付宝扣款顺序设为仅银行卡①」这一步必须在 App 外手动做（写进新手引导） |

> 最后一条最重要：**App 管不了你的钱，只能管你的注意力。** 真正的锁是「支付宝扣款顺序 = 仅银行卡①，余额宝/小荷包不递补」这个手动设置，App 首页要用 3 天时间反复提醒这一点。

## 十二、行为设计 6 条硬规则（决定它会不会被卸载）

1. **首页只显示「剩余」，不显示「已花」。**
2. **全 App 永不出现红色/感叹号。** 超支只是「今天用完了」，灰掉即可。
3. **正反馈必须当天到账**：晚间结算那一屏是全 App 唯一爽点。
4. **预期管理写进 UI**：12 月那行小字不是装饰，是防止你在 12 月弃坑的关键功能。
5. **允许漏记**：任何一天没记，第二天不追问、不补红点、不弹窗。
6. **每一步都能「稍后」**，只有③储蓄那步跳过后弹一次提醒——**只弹一次，绝不唠叨**。

## 十三、命名与视觉

候选名（按推荐度）：**「55块2」**（你自己的数字，最有专属感）｜「今天还有」｜「日额度」｜「离一万」｜「余粮」
视觉：单色底 + 一个强调色（墨绿或暖黄）；**不要彩色饼图**；主数字用大号等宽字体（金额要能一眼比对）；深色模式优先（晚上 22:00 结算场景）。
图标：一只碗 / 一枚硬币 / 一条向下递减的折线。

## 十四、配套可点击原型

同目录 `小程序原型_5519.html` 是四屏可交互原型（真实数据，手机浏览器打开即可点）：能体验记一笔、晚间结算、发薪五步、进度环。先用它验证信息层级和手感，再决定要不要动手写小程序。
